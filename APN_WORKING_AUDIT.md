# 2.15 Working APN

## Поведение

База — выбранный пользователем рабочий интернет-APN, отдельно для каждой SIM. Заводской APN не считается рабочим автоматически. Нет привязки к оператору, стране, адресу APN или ID базы. Работоспособность интернета пользователь подтверждает перед сохранением.

Сохранение читает предпочитаемый APN заново, сверяет подписку/cardId до и после чтения и сохраняет схему 2: target, выбранный ID, имя, APN, numeric, type, protocol, roaming_protocol, carrier_enabled, время. Разрешены пустой numeric и числовой код, отличающийся от исходной SIM. Это важно для вручную созданных и выбранных пользователем профилей. Ограничение internet() сохраняется: нужен включённый профиль с default/*, исключены IMS/XCAP/экстренные профили и профили только MMS.

Снимки прежней схемы не удалены, но не используются как подтверждённый рабочий выбор: их нужно сохранить заново. Сохраняются только основные параметры, не пароли, прокси или параметры аутентификации. Это ограниченная запись для восстановления выбора существующего APN, не полная резервная копия и не средство создания профиля.

## Подготовка и подтверждение

Совпадение ищется только в текущем SIM-filtered списке, по всем сохранённым основным полям кроме ID. Совпадение только по адресу APN более не принимается. Различие protocol, roaming_protocol, type, numeric, имени, адреса или enabled отклоняет профиль. Если найден сохранённый ID, он используется только при совпадении всех этих полей. При смене ID допускается единственное точное совпадение. Если таких строк несколько, пользователь выбирает конкретную; подготовка заново читает список и проверяет соответствие. Удалённый или изменённый профиль не создаётся и не редактируется.

Если выбранный APN уже равен совпавшему сохранённому, возвращается APN_ALREADY_SELECTED без update. Иначе создаётся одноразовый 120-секундный ticket; повторное нажатие показывает существующий и будущий профили, протоколы, SIM и подтверждение. Непосредственно перед update сверяются SIM, исходный выбор и доступность выбранной строки. После записи предпочитаемый APN читается заново: только совпадение с ожидаемой строкой даёт APN_VERIFIED. Этот статус не доказывает доступность интернета/IMS.

## Границы

Единственная запись — content update content://telephony/carriers/preferapn/subId/{subId} с apn_id конкретной строки. Нет insert/delete, редактирования содержимого APN, сброса базы/радио, изменения IMS или автоматического запуска при загрузке/применении MCC/MNC. ProcessBuilder получает отдельные аргументы, shell-интерполяции нет. Ограниченные query URI и projection остаются прежними. Неизвестный результат удерживает блокировку и только опрашивается, запись не повторяется.

Новый APN helper имеет отдельный tag sim-region-working-apn/version 2. Старые незавершённые APN-запросы проверяются через прежний tag/version 1; для них не вызывается новый prepareChoice. Выбор канала проверяется также после связывания, чтобы не использовать старый Binder при неудачном bind.

Проверенные на телефоне MCC/MNC, restore и IMS/приватный номер из 2.14 не менялись (исходники backend сравнивались побайтово). Эксперимент APN расположен внутри «Инструменты тестирования».

AOSP TelephonyProvider preferred-APN update contract:
https://android.googlesource.com/platform/packages/providers/TelephonyProvider/+/refs/heads/master/src/com/android/providers/telephony/TelephonyProvider.java

JVM: добавлены случаи отличия заводского и пользовательского профилей при одинаковом APN, пустого/произвольного numeric, смены ID, нескольких совпадений, изменения каждого сохраняемого поля и исключения IMS/XCAP/экстренных записей. Проверка на устройстве версии 2.15 ещё предстоит. Сборка не выполняет команд на телефоне.
